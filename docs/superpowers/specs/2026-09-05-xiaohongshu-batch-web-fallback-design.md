# 小红书批量解析前台兜底设计

## 背景与问题

小红书作者主页能够返回头像、作品封面和作品索引，但批量任务随后访问作品详情页时，部分设备或会话会收到 HTTP 2xx 的降级页面。该页面不包含 `window.__INITIAL_STATE__`，因此所有作品在真正下载前以 `DETAIL_EMPTY` 失败。

单作品解析已有隐藏 WebView 页面快照兜底，能够在普通 HTTP 解析受限时从真实页面环境提取作品状态；作者批次当前完全运行在 WorkManager 中，无法使用必须依附前台生命周期和主线程的 WebView。

## 目标

- 普通 HTTP 解析仍是首选，避免所有作品都启动 WebView。
- 小红书作品遇到 `DETAIL_EMPTY` 等页面状态缺失错误时，自动转入前台隐藏 WebView 顺序解析。
- 页面本身不展示给用户，只显示明确的准备进度、前台要求和暂停状态。
- 切换页面、进入后台或锁屏时暂停兜底解析，返回作者详情后继续未完成作品。
- 解析进度持久化；进程被系统回收后，不重复已经完成的作品。
- 单个作品失败不阻断其他作品，真正下载仍使用现有任务、目录、日志和受控并发链路。

## 非目标

- 不实现或复制小红书 `x-s`、`x-t`、`x-s-common` 等动态签名算法。
- 不在 WorkManager 或 Application 上下文中创建无界面 WebView。
- 不改变抖音、知乎的批量解析行为。
- 不把小红书网页暴露在批量准备界面中。

## 总体架构

批次拆为“详情准备”和“下载提交”两个阶段。

1. 批次建立后，后台协调器首先尝试普通 HTTP 解析。
2. 解析成功的作品立即保存规范化的 `TaskSpec` 草稿，但暂不丢失其批次关联。
3. 小红书作品因页面状态缺失而失败时，批次状态改为 `WAITING_FOREGROUND`，对应作品改为 `WEB_REQUIRED`，而不是直接标记失败。
4. 作者详情页面观察到待前台解析作品后，显示提示与准备进度，并复用隐藏 WebView 加载该作品规范链接。
5. WebView 得到页面快照后，由现有 `ParserGateway` 使用 Cookie 和快照完成解析；结果持久化，然后继续下一项。
6. 所有可准备作品处理完成后，批次协调器提交已准备的任务到现有下载调度器。下载并发限制维持现状。

普通 HTTP 与 WebView 共用同一个作品结果归一化和 `TaskSpec` 构造入口，避免两条路径在质量选择、保存目录或作者关联上发生差异。

## 数据与状态

`batch_works` 增加以下持久化信息：

- `status` 扩展为 `QUEUED`、`PARSING`、`WEB_REQUIRED`、`PREPARED`、`SCHEDULED`、`FAILED`、`PAUSED`。
- `prepared_task_id`：已创建但尚未提交或已经提交的任务 ID。
- `source_url`：刷新作者页后实际使用的、包含安全上下文的规范作品链接。
- `attempt_count`：前台页面解析次数，用于限制循环重试。
- `error`：脱敏后的最后错误。

`download_batches.status` 扩展 `PREPARING`、`WAITING_FOREGROUND`、`PREPARED`、`SCHEDULED`、`PAUSED` 和 `FAILED`。

Room 采用仅新增列且提供默认值的迁移，保留已有作者、批次和任务数据。旧批次没有准备状态时继续按原逻辑读取。

规范化解析结果不直接以大型 JSON 塞入批次行；成功时沿用任务仓库建立任务记录，并在真正提交前保持排队状态。这样可复用现有 TaskSpec 存储和进程恢复能力，也避免重复保存大量图片 URL。

## 前台交互

用户确认批量设置后，如果批次包含小红书作品，设置页或确认弹窗显示：

> 部分小红书作品可能需要页面环境准备。准备期间请保持应用在前台；切到后台、锁屏或离开作者页面会暂停，返回后可继续。

进入 WebView 兜底后，作者详情顶部显示不可忽略但不阻塞返回操作的进度区域：

- `正在准备小红书作品 3/14`
- `请保持应用在前台`
- 当前作品标题或缩略图（有缓存时）
- “暂停”按钮

隐藏 WebView 保持透明且不可交互，不显示小红书网页。用户离开作者详情、应用进入后台或设备锁屏后，当前加载停止，批次标记为 `PAUSED`，界面显示“准备已暂停，返回后继续”。返回该作者详情时提供“继续准备”；不自动在用户不知情时恢复。

准备阶段与下载阶段分开显示。只有媒体任务进入下载器后才计算下载进度，WebView 页面加载不计入下载百分比。

## 解析流程与重试

每个作品的流程为：

1. 使用最新规范 URL、当前 Cookie 和浏览器导航请求头尝试普通解析。
2. 若成功，建立任务草稿并标记 `PREPARED`。
3. 若错误为 `DETAIL_EMPTY`、`URL_RESOLVE_FAILED` 或可识别的页面状态缺失，标记 `WEB_REQUIRED`。
4. 隐藏 WebView 顺序加载 `WEB_REQUIRED` 作品；一次只加载一个，降低内存占用和风控概率。
5. 快照成功后再次解析并建立任务草稿。
6. 单个作品最多进行两次 WebView 页面准备。仍失败时标记 `FAILED`，继续下一项。
7. 出现明确 `LOGIN_REQUIRED` 时暂停整个准备过程，提示用户完成小红书登录后继续。
8. 出现明确 `CONTENT_UNAVAILABLE` 时将远端状态标记为不可用，不再重试。

作者主页刷新只用于更新作品规范 URL 和安全参数，不再把“主页刷新成功”误认为“详情可解析”。诊断日志记录是否携带 `xsec_token`，但不记录 token 值或完整查询字符串。

## 生命周期与恢复

- WebView 只存在于 Compose 前台页面，并由生命周期事件驱动暂停和销毁。
- 每完成一个作品就写入数据库，不把整个批次进度只保存在 ViewModel 内存中。
- 页面重组不会重复当前作品；以数据库中的 `WEB_REQUIRED`、`PARSING` 和 `PREPARED` 状态为准。
- 进程异常退出后，将遗留的 `PARSING` 恢复为 `WEB_REQUIRED`，用户返回作者详情后继续。
- 用户取消批次时停止 WebView，取消尚未提交的任务草稿，并保留已经完成下载的任务及文件。
- 没有待前台解析项时，后台 Worker 可独立完成准备和下载提交。

## 错误与日志

新增或补充日志事件：

- `WORK_HTTP_PARSE_STARTED` / `WORK_HTTP_PARSE_FAILED`
- `WORK_WEB_REQUIRED`
- `BATCH_FOREGROUND_REQUIRED`
- `WORK_WEB_PARSE_STARTED`
- `WORK_WEB_SNAPSHOT_READY`
- `WORK_WEB_PARSE_SUCCEEDED` / `WORK_WEB_PARSE_FAILED`
- `BATCH_PREPARATION_PAUSED` / `BATCH_PREPARATION_RESUMED`
- `BATCH_PREPARATION_COMPLETE`

日志包括批次 ID、作品键、作品类型、尝试次数、快照字节数、最终主机和是否携带安全参数；所有 Cookie、token 和完整查询字符串继续脱敏。

失败文案区分：需要登录、页面受限、作品不可用、网络错误和页面结构变化。批次摘要展示成功准备、下载中、失败和等待继续数量。

## 测试与验收

单元测试覆盖：

- `DETAIL_EMPTY` 转换为 `WEB_REQUIRED`，而不是直接失败。
- 普通解析成功不启动 WebView。
- WebView 快照成功后建立与普通路径一致的任务设置。
- 最多两次页面准备、单项失败隔离和登录暂停。
- `PARSING` 状态在进程恢复时回退到 `WEB_REQUIRED`。
- URL 安全参数只记录存在性，不泄露具体值。
- Room 迁移保留旧任务、作者和批次数据。

界面测试覆盖前台提醒、准备进度、离开页面暂停、返回后继续，以及准备进度不混入下载百分比。

手工验收使用当前失败的 14 个小红书作品批次：头像与预览保持正常；受限详情自动进入隐藏页面准备；可访问作品能够创建并完成下载任务；失败作品给出独立原因；整个过程不展示小红书页面且切后台后不会继续偷偷加载。

## 交付边界

实现提交只包含该兜底链路、数据库迁移、对应测试和必要提示文案。测试 APK 保持 1.6.1，不启用 R8，不推送 GitHub，也不创建 Release。工作区既有的无关删除和临时文件不纳入提交。
