# 知乎问题归档与预览续播设计

日期：2026-09-06

## 背景与范围

聚合下载器已经支持知乎单篇回答、文章、想法和视频，也支持作者作品批量下载。当前不支持只有
`/question/{questionId}` 的问题链接，视频预览在应用进入后台时还会释放播放器并丢失进度。

本次增加两个互相独立的能力：

1. 输入知乎问题链接后，归档当前账号可见的全部回答，并为每条回答保存全部可见评论；
2. 视频或音频预览切换到其他应用时只暂停，返回后保留播放位置及全屏/缩略状态。

“全部”只表示知乎当前向登录账号公开且分页接口能够遍历到的内容，不包含已删除、审核中、
折叠后不可访问、付费或其他无权限内容。不支持 `/topic/{topicId}` 标签话题页。本次不模仿迅雷
重构全局下载队列，不改变现有 WorkManager 按作品建立子任务的机制。

## 播放器生命周期

应用进入后台时关闭声音并暂停当前播放器，但不释放播放器、不清空 `MediaPreviewState`，也不
清空当前全屏任务 ID。返回应用后：

- 切出前是全屏，仍显示全屏并停在原位置；
- 切出前是卡片内缩略预览，仍保持缩略预览并停在原位置；
- 不自动恢复播放，用户点击播放后从保留位置继续；
- 播放进度、静音状态及已选择媒体保持不变。

离开任务页面、关闭预览、切换任务和删除任务仍释放播放器。Android 在后台彻底杀死应用进程
后不恢复播放进度；持久化跨进程观看历史不在本次范围。

## 问题入口与界面

`ZhihuSourceResolver` 增加 `QUESTION` 类型。首页“作品解析”接受规范问题链接，查询参数不会
进入稳定键。解析成功后进入问题归档详情页，显示：

- 问题标题、问题 ID、来源链接；
- 知乎报告的回答数量、已加载数量和最后刷新时间；
- 当前批次完成、失败、等待和暂停数量；
- 每页约 20 条回答及上一页/下一页；
- 回答作者、摘要、赞同数、评论数、本地状态和失败原因。

下载前展示设置：下载当前页或全部回答、是否包含评论。评论默认包含；正文图片和内嵌视频沿用
知乎文档现有的“Markdown + 全部可下载媒体”策略。开始后，任务页只显示一个知乎问题入口，
子回答任务不堆叠在普通任务列表。点击入口进入问题详情并查看或重试具体回答。

问题入口参与“知乎”平台筛选。删除入口时可选择只删除记录或同时删除整个问题目录；正在运行
时先取消该问题的批次和子任务。问题详情返回后保留分页和列表滚动位置。

## 数据模型与数据库

新增问题归档、回答索引、问题批次和批次回答记录：

- `ZhihuQuestionEntity`：问题 ID、标题、规范 URL、回答总数、保存目录、归档状态、分页游标、
  首次创建及最后刷新时间；
- `ZhihuQuestionAnswerEntity`：问题 ID、回答 ID、作者、摘要、赞同数、评论数、排序位置、远端
  状态、本地状态及关联任务 ID；
- `ZhihuQuestionBatchEntity`：批次设置、总数、完成数、失败数、暂停原因及 WorkManager ID；
- `ZhihuQuestionBatchAnswerEntity`：回答准备、调度和错误状态。

问题稳定键为 `zhihu-question:{questionId}`，回答稳定键为 `zhihu-answer:{answerId}`。回答下载仍
生成现有 `TaskSpec`，增加可选 `questionArchiveKey`、问题子任务标记和评论下载请求。历史任务缺少
这些字段时保持原行为。Room 使用只增字段/表的迁移，不重写现有任务 JSON。

主任务列表只观察问题级汇总；问题详情按问题 ID 和页码读取回答，避免一次渲染全部回答。现有
全局任务调度、并发策略和普通任务刷新逻辑不在本次重构。

## 分页、解析与风控

问题数据源负责获取问题资料和回答分页。每页响应保存后按回答 ID 去重，并保存下一页游标或
偏移量。下载“全部回答”时沿用现有作者批量准备方式：逐条解析回答详情，成功后创建独立下载
任务；单条失败不回滚其他回答。

遇到 HTTP 403、明确登录要求或风控时停止继续准备，把尚未处理的回答标记为暂停，而不是失败，
并保留问题分页游标和批次位置。用户登录、刷新环境或稍后点击继续后从断点恢复。批量数量较大
时明确提示可能造成手机卡顿或触发知乎风控。问题刷新失败时保留上次缓存，不把未探测到的回答
推断为已删除。

如果问题回答列表或回答详情只能通过 WebView 页面状态取得，复用现有知乎 WebView 快照回退；
不会绕过验证码、登录、付费或内容权限。

## 评论获取与 Markdown

每条回答正文解析成功后记录回答 ID 和评论数量。下载任务使用当时有效的知乎 Cookie 分页获取
一级评论；一级评论声明仍有未返回回复时，再分页获取其子评论。所有记录按评论 ID 去重，保留：

- 作者名称和可用的作者主页；
- 发布时间、更新时间和赞同数；
- 评论正文；
- 回复目标、父评论 ID 和可见回复关系。

评论分页边读取边写临时文件，不把全部评论正文写入 `TaskSpec` 或长期保存在 Room。下载完成后
生成标准 Markdown：

```markdown
# 评论（共 126 条）

## 张三 · 2026-09-06 · 32 赞

这是一条一级评论。

> 李四 回复张三 · 5 赞
> 这是回复内容。
```

评论获取部分失败时保留已取得部分，在文件顶部和任务提示中写明“不完整”及停止页码；回答
正文和媒体已成功时不因评论失败删除它们。明确没有评论时仍生成简短的 `comments.md`，说明该
回答下载时未发现可见评论。

应用内回答预览继续使用结构化 `DocumentContent`，正文底部增加“查看评论（N）”入口，按需读取
并展示 `comments.md`；不会把几千条评论预先加入正文块或任务列表状态。

## 文件布局与索引

每个问题使用稳定目录，回答各自位于子目录：

```text
知乎/
  问题标题_问题ID/
    index.md
    answers/
      回答ID_作者/
        answer.md
        comments.md
        media/
```

`index.md` 保存问题标题、来源、归档时间和回答链接清单。回答 Markdown 末尾使用相对链接指向
`comments.md`，问题索引使用相对链接指向各回答。目录首次建立后不因标题变化自动重命名。

默认公共目录和 SAF 均复用现有相对子目录校验与发布逻辑。删除单条回答不会自动删除问题目录；
问题目录内已无文件时，问题入口显示本地内容已删除并允许重新下载或删除记录。

## 错误、日志与恢复

问题、回答和评论分别记录阶段日志，包含问题 ID、回答 ID、页码、HTTP 状态、分页结束标记和
脱敏错误；不记录 Cookie、完整签名参数或评论中的敏感请求信息。

批次状态区分：准备回答、下载正文媒体、获取评论、生成索引、因登录/风控暂停、部分完成、全部
完成和取消。重新下载回答时先确认远端解析成功，在新文件完整发布后再清理旧文件，继续沿用现有
事务式替换原则。

## 测试与提交边界

测试覆盖：问题链接识别、超长数字 ID、回答分页结束与去重、评论及子评论分页、Markdown 转义、
部分评论失败、数据库迁移、问题子任务隐藏、聚合状态、分页滚动恢复，以及播放器后台暂停后保留
位置和全屏/缩略状态。

提交拆分为：

1. 本设计文档；
2. 播放器后台续播修复；
3. 知乎问题模型、分页、页面和批次下载；
4. 评论下载、Markdown、应用内入口和恢复测试。

现有工作区中的无关删除及临时文件不会纳入提交。
