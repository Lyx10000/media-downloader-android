# Android 任务文件管理器设计

日期：2026-09-04

## 背景

任务卡当前通过目录 `Intent` 打开系统或厂商文件管理器，并已经附带读写 URI 授权。但
Android 没有要求接收方必须提供重命名、删除、移动或复制界面的统一协议，vivo 等设备
可能只显示只读内容。继续增加厂商包名和私有 Activity 只能改善个别机型，不能形成稳定
能力。

应用已有完整的任务输出清单，每个输出包含 URI、显示名称、MIME 类型和大小；同时已有
分享、预览、文件状态检查、MediaStore、SAF 和诊断日志基础。因此新增一个只管理任务登记
文件的应用内文件管理器，由应用自己执行修改，系统目录选择器只负责让用户选择复制或移动
的目标位置。

## 目标

- 从任务卡进入独立的“管理文件”子页面。
- 展示该任务登记的全部图片、视频和音频，包括已缺失项目。
- 支持单选和多选，以及分享、删除、复制、移动和单文件重命名。
- 文件 URI 或名称发生变化后同步更新任务记录，保证预览、分享、删除和状态检查仍然有效。
- 文件操作不依赖外部文件管理器是否提供编辑功能。
- 每次操作记录结构化诊断日志，并对部分失败给出明确结果。
- 继续支持默认 MediaStore 下载目录和用户选择的 SAF 目录。

## 非目标

- 不做通用的全盘文件管理器，不扫描或管理任务记录以外的文件。
- 不递归修改任务目录，不删除用户后来放入任务目录的未知文件。
- 不提供压缩、解压、格式转换、在线同步或回收站。
- 不使用 vivo、OPPO、小米等厂商的私有文件管理器接口。
- 不把复制出的副本加入原任务，也不在删除原任务时清理副本。

## 方案选择

### 采用：应用内任务文件管理器

应用直接通过 `ContentResolver`、MediaStore、`DocumentFile` 或普通文件 API 执行操作。
该方案改动较多，但行为由应用控制，能够覆盖目标机型，并且可以保持任务数据库与实际文件
一致。

### 不采用：继续增强外部目录 Intent

可以继续尝试更多 MIME 类型、包名和 Activity，但接收方仍可忽略写权限或只展示内容。
这无法满足“可操作”的完成标准。

### 不采用：把所有操作塞入任务卡

可以复用当前任务列表，但多选状态、目标目录选择、错误反馈和文件元数据会显著增加卡片复杂
度，也容易与任务级删除、预览和分享混淆。独立子页面的边界更清楚。

## 交互设计

### 入口与页面

任务卡原“文件夹”主操作改为“管理文件”。点击后进入子页面，顶部应用栏提供返回按钮和
任务标题；底部主导航暂时隐藏。页面保留“用系统文件管理器打开原目录”作为低强调辅助
操作。

列表只展示任务 `outputs` 中的项目。每行包含媒体缩略图或类型图标、文件名、格式、真实
大小和可用状态。缺失项使用降低强调的样式并标注“文件已删除”，不能被选择执行文件操作。

正常状态点击可用项目使用系统查看器打开该文件；长按进入多选状态。多选状态中点击行或
复选框切换选择，顶部显示已选数量并提供退出选择。底部操作栏提供：

- 分享：沿用现有分享兼容逻辑；混合媒体类型时提示按类型分别选择。
- 复制：允许多选，打开系统目录选择器选择目标目录。
- 移动：允许多选，打开系统目录选择器选择目标目录。
- 删除：允许多选，显示包含数量和不可恢复说明的确认对话框。
- 重命名：仅选择一个文件时可用，使用带校验的输入对话框。

约 48dp 的触控目标、语义化主题色、`ListItem`、`Checkbox`、`TopAppBar`、确认
`AlertDialog` 和操作反馈 `Snackbar` 遵循现有 Material 3 体系。

### 文件名规则

重命名输入只修改文件名主体，默认保留原扩展名。名称不能为空，不能包含 `/`、反斜杠、
NUL 或 `.`、`..`，去除首尾空白。目标目录已有同名文件时，重命名直接提示冲突，不覆盖。

复制和移动遇到同名文件时自动使用 `名称 (1).扩展名`、`名称 (2).扩展名`，不覆盖现有
文件。

## 状态与组件边界

### AppContent

在现有手写顶层目的地状态之外增加可空的“正在管理的任务 ID”。存在该 ID 时显示文件管理
子页面并隐藏顶层底部导航；返回后回到任务列表。Activity 重建后允许退回普通任务列表，
不需要持久化临时选择状态。

### TaskFileManagerScreen

只负责渲染文件列表、选择状态、对话框和目录选择器。它不直接执行磁盘操作。目录选择器取得
Tree URI 后申请可持久化读写权限，并把操作请求交给 ViewModel。

### TaskFileOperationCoordinator

新增协调器，负责串行执行重命名、删除、复制和移动。它读取最新任务记录，以 URI 为稳定
标识重新匹配选择，避免页面数据过期；完成后通过仓库更新输出记录并触发文件状态刷新。

协调器不处理 UI，不启动 Activity，也不持有 Compose 状态。

### ManagedFileGateway

封装 Android 存储 API：查询可读性和元数据、打开输入流、在目标 Tree URI 创建唯一文件、
重命名、删除和回滚刚创建的目标。协调器依赖该接口，使操作排序、部分失败和数据库更新能够
用假实现做单元测试。

实现按 URI 类型分派：

- `content://media`：使用 `ContentResolver` 和 MediaStore 更新或删除。
- SAF 文档 URI：使用持久 Tree 授权、`DocumentFile` 和 `ContentResolver`。
- 旧 `file://` 输出：只在已解析的具体文件路径上执行普通文件操作，不进行递归操作。

### DownloadTaskRepository

沿用 `replaceOutputs` 更新成功重命名或移动后的输出。删除操作保留原输出记录，使现有
`PARTIAL` / `MISSING` 语义继续表示预期文件被删除；因此全部删除后任务自动变灰，仍可完整
重新下载。

## 操作语义与数据一致性

### 重命名

1. 停止正在播放或预览的目标任务媒体。
2. 用最新任务记录确认 URI 仍存在且可写。
3. 检查目标名称是否合法且不存在冲突。
4. 执行存储重命名，再重新查询实际 URI、名称、MIME 和大小。
5. 仅替换对应 `TaskOutput`，其他输出顺序不变。

存储操作失败时不修改数据库。存储成功但数据库更新失败时记录严重诊断事件，并立即刷新
文件状态；页面重新进入时通过实际 URI 尽力恢复，绝不谎报原名称仍可用。

### 删除

逐个删除所选文件并记录每项结果。任务输出记录保持不变，随后运行现有文件状态检查：仍有
其他输出时为 `PARTIAL`，全部不存在时为 `MISSING`。部分删除失败不会回滚已经明确删除的
文件，界面报告成功数与失败数。

### 复制

逐个把源内容流复制到用户选择的 Tree URI。每个目标先创建再写入；写入失败时删除该不完整
目标。复制成功的副本不加入任务 `outputs`，因此任务预览、分享和任务级删除仍指向原文件。

### 移动

每个文件按“复制到目标、校验写入、删除源文件、更新该输出记录”的顺序执行。只有源删除
成功才把任务输出替换成目标 URI。若源删除失败，优先删除刚创建的目标作为回滚，并保留原
任务记录；回滚也失败时日志明确记录可能存在未跟踪副本。

多文件移动按项目独立提交：已成功移动的文件更新到新 URI，失败文件继续引用原 URI。这样
任意时刻任务记录都尽量指向真实可访问文件，且无需不可实现的跨 Provider 原子事务。

任务 `TaskSpec` 的默认下载根目录和任务子目录不随单个文件移动而变化。重新下载仍写入原
任务保存位置；管理页面通过每个输出 URI 管理已移动文件。“用系统文件管理器打开原目录”
仍指向最初下载目录，并在文案中明确“原目录”。

## 并发与生命周期

- 同一任务同一时间只执行一个文件操作；操作期间禁用返回以外的修改操作。
- 文件操作在 IO 调度器运行，不阻塞 Compose 主线程。
- 开始操作前停止该任务的音视频播放，避免重命名、移动或删除正在读取的文件。
- 页面离开不取消已经开始的复制或移动，以免留下截断文件；进度通过 ViewModel 状态继续保留。
- 下载中、合成中、排队中或删除中的任务不允许进入文件修改模式。

## 权限与目标目录

复制和移动通过 `ACTION_OPEN_DOCUMENT_TREE` 选择目标目录，并申请读、写和持久化授权。若
Provider 不允许持久化，当前操作仍可使用本次临时授权，但移动后的目标无法保证下次启动可
访问；这种情况下禁止移动，只允许复制并提示原因。

默认 MediaStore 输出优先依赖应用对自身创建内容的所有权。旧安装遗留、授权失效或 Provider
拒绝写入时返回可执行错误，不请求无关权限。“所有文件访问”只用于现有默认物理目录能力，
不是 SAF 目标目录的替代品。

## 错误处理与日志

用户反馈包含操作类型、成功数、失败数和首个失败原因。重命名冲突、文件已不存在、目标目录
不可写、空间不足、授权失效、源删除失败和回滚失败分别记录。

日志事件至少包括：

- `FILE_MANAGER_OPENED`
- `FILE_OPERATION_REQUESTED`
- `FILE_COPY_RESULT`
- `FILE_MOVE_RESULT`
- `FILE_RENAME_RESULT`
- `FILE_DELETE_RESULT`
- `FILE_OPERATION_COMPLETED`

日志记录任务 ID、URI authority、MIME 类别、字节数和脱敏后的错误，不记录 Cookie、远程
下载 URL、用户目录中的无关文件或完整本地路径。

## 测试策略

### 单元测试

- 文件名校验、扩展名保留和同名序号生成。
- 单文件重命名成功、冲突、存储失败和输出记录替换。
- 多文件复制成功与部分失败，不修改原任务输出。
- 移动成功时替换 URI；源删除失败时回滚目标并保留原输出。
- 删除后保留预期输出，并得到 `PARTIAL` 或 `MISSING` 状态。
- 过期选择、缺失文件、混合媒体分享限制和重复操作防护。

### Compose/UI 测试

- 从任务卡进入、返回以及底部导航隐藏。
- 长按进入多选、选择计数、全选/取消和缺失项不可选。
- 单选时启用重命名，多选时禁用重命名。
- 删除确认、非法名称提示、目录选择取消和操作中禁用状态。

### 构建与设备验收

- 运行 Android 单元测试、Compose 测试、Lint、Python 测试和 release 构建。
- 一加 13T 验证 MediaStore 与 SAF 下全部操作。
- vivo Y70s 验证应用内操作不依赖厂商文件管理器编辑模式。
- 华为系不作为专项适配和发布阻断项。

## 完成标准

- vivo 等只读外部文件管理器环境中，用户仍可从应用内完成全部六类操作。
- 重命名和移动后，任务预览、分享、删除与状态检查使用新的真实 URI。
- 复制副本不会被任务删除误删。
- 删除部分或全部任务文件后，任务卡分别呈现部分缺失或灰色缺失状态。
- 任一部分失败都不会覆盖现有文件，也不会让数据库整体指向不存在的目标。
- 新 APK 使用与 1.2.1/1.2.2 相同的 v2 发布证书，可覆盖安装。
