# Android 知乎图文与视频支持设计

日期：2026-09-04

## 背景

聚合下载器目前支持抖音和小红书，平台解析结果统一进入 `ParseResult`，由 WorkManager 和
`DownloadExecutor` 在手机本地完成下载、媒体处理与公共目录发布。知乎的独立视频能够映射到
现有视频模型，但文章、回答和想法属于混合内容：同一条内容可能按顺序包含文字、多张图片、
GIF 和多个知乎视频。现有 `MediaKind.VIDEO` / `MediaKind.IMAGE` 二选一模型无法表达这种结构。

本次工作增加知乎平台支持，并为混合内容增加有序文档模型。知乎文章、指定回答和想法保存为
Markdown 与本地媒体目录；独立视频继续复用现有清晰度选择、拆轨与下载模式。实现保持纯
Kotlin、本地运行，不引入远程中转服务。

## 用户目标

- 支持知乎文章、指定回答、想法和独立视频链接。
- 图文内容同时保存文字、图片和知乎内嵌视频，并保持原文顺序。
- 文档保存为 Markdown，媒体保存为原始文件，由 Markdown 使用相对路径引用。
- 独立视频允许选择接口返回的不同清晰度。
- 混合文档内的每个视频自动选择当前可取得的最高候选，不逐个要求用户选择。
- 复用知乎平台 Cookie，避免每个作品重复准备环境或要求登录。
- 保持抖音、小红书、历史任务、预览、分享、删除和文件管理行为兼容。

## 第一版范围

### 支持

- `https://zhuanlan.zhihu.com/p/{articleId}` 文章；
- 知乎文章的等价 `www.zhihu.com/tardis/zm/art/{articleId}` 地址；
- `https://www.zhihu.com/question/{questionId}/answer/{answerId}` 指定回答；
- 可明确提取回答 ID 的等价分享地址；
- `https://www.zhihu.com/pin/{pinId}` 想法；
- `https://www.zhihu.com/zvideo/{videoId}` 独立视频；
- 上述文档正文中的图片、动态图和知乎自有内嵌视频；
- 分享文本中混有标题、口令、查询参数和中文标点的链接提取。

### 不支持

- 只有 `/question/{questionId}`、没有指定回答的链接；一个问题可能包含大量回答，第一版不猜测
  下载范围；
- 盐选、付费专栏、私密、已删除或当前账号无权访问的内容；
- 知乎 Live、课程、播客和其他独立音频产品；
- 哔哩哔哩、YouTube 等外部平台嵌入视频的跨平台下载；Markdown 只保留其原链接；
- 评论、推荐内容、相关回答、头像、表情资源和广告图片；
- 绕过登录、付费或内容权限限制。

## 方案选择

### 采用：向解析契约增加可选的有序文档模型

`ParseResult` 保持为跨平台边界，在其中增加可选 `document` 字段。文档由有序内容块和独立
媒体资源组成：内容块负责表达阅读顺序与排版，媒体资源负责候选 URL、视频档位、封面和最终
文件名。下载完成后，Markdown 渲染器根据媒体下载结果把资源引用改成本地相对路径。

该方案能准确表示文字、图片和视频混排，同时让旧平台继续使用现有顶层字段。序列化字段均为
可选值，历史任务不需要数据库迁移。

### 不采用：保存 HTML 后进行字符串替换

该方式改动较小，但无法可靠处理懒加载图片、嵌套标签、多个内嵌视频、HTML 实体和复杂内容，
也难以保证替换后资源顺序及路径安全。

### 不采用：重做全部平台为通用资源图

全面统一抖音、小红书和知乎的内部模型长期更整齐，但会扩大本次回归面。当前只增加向后兼容
的文档分支，等更多文档型平台出现后再评估统一迁移。

## 数据模型

### 媒体类型

`MediaKind` 增加 `DOCUMENT("document")`。现有 `VIDEO` 和 `IMAGE` 的序列化值及行为不变。

### DocumentContent

`ParseResult.document` 为可选 `DocumentContent`，包含：

- `type`：`ARTICLE`、`ANSWER` 或 `PIN`；
- `title`、`author` 和规范来源地址；
- 按正文顺序排列的 `blocks`；
- 以稳定资源 ID 索引的 `assets`；
- 解析阶段产生的非致命警告。

文档内容写入 `ParseResult` 现有 JSON 时使用新键；`fromJson` 缺少该键时返回 `null`。旧任务
和旧版本产生的 JSON 保持可读。知乎的新式内容 ID 可能超过 JavaScript 的安全整数范围，平台
ID、问题 ID、回答 ID、媒体 ID 和资源 ID 在整个模型及 JSON 中一律按字符串处理。

### 内容块

第一版内容块覆盖：

- 段落与换行；
- 一级至六级标题；
- 有序列表、无序列表和列表项；
- 粗体、斜体、删除线和行内代码；
- 普通链接；
- 引用块；
- 代码块及可选语言；
- 图片引用；
- 知乎视频引用；
- 无法可靠转换的受控 HTML 片段。

内容块不保存任意可执行脚本。`script`、`style`、事件属性、iframe 和不安全 URL 协议在解析
边界被移除。外部视频 iframe 只转换为普通来源链接。

### 文档媒体资源

图片资源包含稳定 ID、说明文字、页面明确提供的候选 URL 和建议扩展名。视频资源包含稳定
ID、封面候选与多个 `MediaVariant`。资源 ID 只在任务内部使用，最终文件名按正文顺序生成：

- `media/image_001.<真实扩展名>`；
- `media/video_001.mp4`；
- 可用时保存 `media/video_001_cover.<真实扩展名>`。

视频候选根据规范化 URL、分辨率、码率和大小去重。知乎某些接口把码率以 Kbps 返回；当字段
量级与文件大小/时长及接口结构表明单位为 Kbps 时，转换为 bps 后再进入现有排序和显示逻辑。
不使用 `ld`、`sd`、`hd` 名称代替实际媒体参数。

## 平台识别与解析

### SourcePlatform

增加 `SourcePlatform.ZHIHU`：

- `wireValue = "zhihu"`；
- `displayName = "知乎"`；
- 首页和 Referer 使用 `https://www.zhihu.com/`；
- 匹配 `zhihu.com` 及其合法子域，不接受相似恶意域名；
- 允许匿名优先解析。

### ZhihuSourceResolver

解析器先去除查询参数对 ID 识别的干扰，再按明确路由识别文章、回答、想法和独立视频。规范
地址不保留 `share_code`、`utm_psn` 等追踪参数。只有问题 ID 而没有回答 ID 时返回稳定的
`UNSUPPORTED_QUESTION`，提示用户分享具体回答。

### 数据请求优先级

1. 使用已有 Cookie（如有）请求对应公开 JSON 数据；
2. 没有 Cookie 时先尝试匿名公开 JSON；
3. JSON 被拒绝或缺少正文时，请求规范页面并提取 `js-initialData`、`__NEXT_DATA__` 或等价的
   页面初始状态；
4. 对正文中的知乎内嵌视频 ID，请求知乎视频详情或播放列表接口；
5. 所有接口均不可用时返回类型化错误，不使用远程解析服务。

具体 API 主机可能因知乎调整而变化，解析器把 API 路径和响应归一化分离。接口请求使用
OkHttp、知乎 User-Agent、Referer、Accept 和 WebView Cookie；响应必须关闭，超时和跳转受控。

### 正文提取

`ZhihuRichContentParser` 使用容错 HTML 解析，不对正文执行正则替换。只读取目标文章、回答或
想法实体自己的正文 HTML/结构化内容。图片候选依次考虑正文节点明确给出的原始、实际加载和
默认地址；仅在可信知乎图片主机上移除明确的缩放参数，不猜测不存在的“原图”路径。

知乎内嵌视频通过正文节点中的稳定视频标识关联播放列表。外部视频节点转换成普通链接。重复
图片和重复视频在保持第一次出现位置的前提下去重。

## Cookie 与环境准备

Cookie 是知乎平台级状态，不按作品保存。自动流程为：

1. 已有 Cookie 时直接复用；
2. 没有 Cookie 时先匿名解析；
3. 只有“无 Cookie且返回明确认证/风控错误”时，后台静默加载一次知乎首页以取得匿名 Cookie
   和环境参数；
4. 同一次解析最多自动准备一次；
5. 已有 Cookie 后仍返回 `403` 时不循环加载，只显示知乎风控或登录状态提示；
6. 真正可交互的登录页面只由用户从设置页主动打开；
7. 登录一次后 Cookie 复用于后续知乎任务，直到过期、被清除或平台使其失效。

后台环境准备不等于账号登录，不要求输入账号密码，也不显示知乎页面。付费或私密内容不会
因为重复准备环境而变为可下载。

## 用户界面

### 解析确认页

文档任务显示平台、内容类型、标题、作者、图片数量和知乎内嵌视频数量，并提供“下载完整内容”
按钮。文档任务不显示视频四模式，也不逐个显示视频清晰度。

独立知乎视频沿用现有清晰度列表和四种下载模式：合成并保留、保存分轨、不含音频的视频轨、
仅音频。视频已经内嵌音频时继续使用现有无重新编码拆轨逻辑。

### 任务页

任务卡片显示“知乎”来源标记。文档下载完成后，现有预览区域展示全部成功下载的图片和视频；
Markdown 不在卡片内渲染，通过文件管理器或分享操作。离开任务页时的音视频暂停规则不变。

### 设置页

解析环境区域增加“登录或刷新知乎环境”按钮，打开现有全屏可交互 WebView。自动解析流程只
使用隐藏环境准备，不自动弹出登录页面。

## Markdown 输出

### 目录结构

文章、回答和想法分别使用 `article.md`、`answer.md` 和 `pin.md`：

```text
任务目录/
├── article.md
└── media/
    ├── image_001.jpg
    ├── image_002.gif
    ├── video_001.mp4
    └── video_001_cover.jpg
```

Markdown 顶部写入标题、作者和原始知乎链接，之后按内容块顺序渲染正文。图片使用相对路径：

```markdown
![图片说明](media/image_001.jpg)
```

知乎视频同时提供稳定的可点击链接和兼容阅读器的 HTML 增强标签：

```markdown
[▶ 点击播放视频](media/video_001.mp4)

<video controls src="media/video_001.mp4"></video>
```

不同 Markdown 阅读器可能不支持 `<video>`，可点击链接是最低兼容保证。复杂公式、表格等
无法稳定转为标准 Markdown 时，保留经过清理的内嵌 HTML。图片和视频不会转为 Base64，避免
体积增加和阅读器卡顿。

## 下载与存储

### 文档下载流程

1. 在任务缓存目录创建 `media/`；
2. 按正文首次出现顺序下载图片和视频；
3. 图片尝试全部候选，按真实文件头确定扩展名；
4. 每个文档视频选择排序第一的最高候选，并复用现有大文件 CDN 加速和回退；
5. 保存可用视频封面；
6. 根据成功与失败资源生成 Markdown；
7. Markdown 在缓存目录成功生成后，再发布媒体和 Markdown，持续更新任务输出记录；
8. 完成后清理内部缓存。

文档视频按接口返回字节保存，不重新编码。独立视频仍可按用户选择拆轨；文档内视频直接保存
含音频的完整 MP4，不额外生成视频轨和音频轨。

### 部分媒体失败

单个资源会尝试全部候选和现有重试策略。仍失败时继续处理其他资源，Markdown 对该资源保留
原网络地址，并在文末列出未能离线保存的资源。只要 Markdown 成功生成和发布，任务保持完成
状态，阶段显示“已完成（有 N 项媒体未下载）”，日志记录资源序号、类型、主机和脱敏错误。

如果 Markdown 无法生成或保存，任务失败；文档发布过程中产生的本次新文件执行尽力回滚，
并把无法清理的 URI 写入任务输出和诊断日志，避免静默留下孤立文件。独立视频继续使用现有
严格失败语义。

### 相对子目录

`PublicStorage` 增加经过校验的可选相对子目录参数。第一版只需要空目录和固定 `media`，拒绝
绝对路径、空路径段、`.`、`..`、反斜杠和控制字符。MediaStore 使用任务目录下的嵌套
`RELATIVE_PATH`；SAF 只在当前任务目录下创建或复用 `media` 子目录。

`TaskOutput` 增加可选 `relativePath`，旧输出默认使用 `displayName`。文件 URI 仍是预览、分享、
重命名和删除的权威标识，因此现有任务操作不依赖手工拼接路径。打开文件夹仍定位任务根目录，
用户可进入 `media/` 管理文件。

普通 Android 多文件分享不保证保留目录层级，因此本次不承诺分享后的 Markdown 相对链接继续
有效，也不自动持久化 ZIP。完整离线结构以任务文件夹为准。应用内文件管理仍允许重命名、
移动和删除文档媒体，但操作前提示这可能使 Markdown 相对链接失效；第一版不自动改写已经
发布的 Markdown。用户从系统文件管理器修改目录时同样遵循这一限制。

## 错误分类与日志

知乎解析器提供稳定错误码：

- `UNSUPPORTED_URL`：不是支持的知乎地址；
- `UNSUPPORTED_QUESTION`：只有问题地址，未指定回答；
- `AUTH_OR_RISK`：认证或风控拒绝；
- `LOGIN_REQUIRED`：内容明确要求登录；
- `CONTENT_RESTRICTED`：付费、私密或当前账号无权访问；
- `CONTENT_UNAVAILABLE`：内容删除或不存在；
- `DETAIL_EMPTY`：响应成功但目标实体或正文为空；
- `MEDIA_EMPTY`：独立视频没有可下载档位；
- `NETWORK` / `HTTP_ERROR`：网络或其他 HTTP 错误；
- `PARSE_FAILED`：未归类结构异常。

日志新增知乎链接类型、请求路径类别、Cookie 是否存在、数据来源（API/页面状态）、内容块数量、
媒体数量、档位数量、去重数量、Markdown 生成结果和部分失败计数。日志不得写入 Cookie、完整
正文、完整媒体查询参数或账号隐私。

## 兼容性

- Room 表结构不变；文档模型和 `relativePath` 位于现有 JSON 字段中，不需要数据库迁移；
- `TaskStatus` 不增加新状态，部分媒体失败通过完成阶段与日志表达；
- 抖音、小红书解析器不创建 `document`，下载分支保持原样；
- 历史 `TaskSpec`、`ParseResult` 和 `TaskOutput` 缺少新字段时使用默认值；
- 应用 ID、下载根目录和当前发布证书不变，继续支持覆盖安装；
- R8 和资源裁剪继续启用，新增 HTML 解析依赖必须确认不会被错误裁剪。

## 测试策略

### URL 与路由

- 文章、Tardis 文章、指定回答、想法和独立视频；
- 分享查询参数、中文标点、混合文本和恶意相似域名；
- 只有问题 ID 时返回 `UNSUPPORTED_QUESTION`；
- 稳定规范地址不含分享追踪参数。

### 解析与归一化

- API 成功、带 Cookie 成功、API 失败后页面初始状态成功；
- 登录、风控、付费、私密、删除和空实体错误映射；
- 单图、多图、GIF、多个知乎视频、外部视频链接和重复媒体；
- 正文之外头像、推荐和广告资源不会进入文档；
- 视频档位按实际参数去重，重复 `ld` / `sd` 不会显示两次；
- Kbps 码率归一化及按分辨率、帧率、码率、大小排序。

### Markdown

- 标题、段落、强调、链接、列表、引用、代码、图片和视频顺序；
- Markdown 特殊字符、文件名和链接安全转义；
- 复杂表格与公式保留清理后的 HTML；
- 成功媒体使用相对路径，失败媒体保留网络地址并生成警告；
- 不生成脚本、事件属性或危险协议。

### 下载与存储

- 文档图片、视频和封面下载到确定性文件名；
- 图片真实格式识别、视频最高候选和大文件分段下载复用；
- MediaStore 与 SAF 的 `media/` 创建、覆盖、发布失败回滚和路径穿越防护；
- 输出 URI 支持预览、多选分享、重命名、复制、移动、删除和文件状态检查；
- 删除任务及下载内容时清理任务根目录与嵌套媒体目录。

### 回归与发布

- 历史任务 JSON 和当前数据库无需迁移即可读取；
- 抖音视频、抖音图文、小红书视频和小红书图文全量测试；
- Android JVM 单元测试、Android 测试编译、Lint、R8 Release 构建；
- 签名 APK 与当前证书一致并支持覆盖安装；
- 无连接真机时明确保留设备验收项，不以本地构建代替真机测试。

均触发知乎 `403`。因此这些回答/文章只作为手机 WebView Cookie 与页面回退的设备验收样本，

- 五个用户样本均能被正确识别，设备可访问时解析到目标内容而非推荐内容；
- 文章、回答和想法生成可读 Markdown，文字与媒体顺序正确；
- 图片、GIF 和知乎视频保存在 `media/`，Markdown 使用有效相对路径；

- 旧任务及抖音、小红书功能无回归；
- Release 测试、Lint、R8、签名和覆盖安装校验通过；
