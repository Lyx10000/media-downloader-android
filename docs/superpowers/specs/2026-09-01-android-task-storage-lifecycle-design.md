# Android 任务与下载文件生命周期设计

日期：2026-09-01

## 背景

Android 应用当前能保存和重试下载任务，但任务记录与公共存储中的文件缺少可靠的关联信息。任务完成后，如果用户在文件管理器中删除部分文件、整个任务目录或下载根目录，应用不能准确反映实际状态。当前重试还会复用任务中保存的旧 CDN 地址，链接过期后成功率不足。

图文作品还有一项独立问题：解析器只使用 `origin_url`、`url_list` 等字段，没有优先读取部分接口返回的 `download_url_list`；Android 数据模型又只保存每张图片的第一个地址，无法在 CDN 地址失效时自动切换。

本设计建立任务记录、存储位置、输出文件和作品恢复信息之间的明确关系，并加入安全删除、外部删除识别和重新解析下载能力。

## 目标

- 删除任务时允许用户选择是否同步删除下载内容。
- 只删除属于该任务的已登记文件，并仅在目录确认为空时删除任务目录。
- 区分文件完整、部分缺失、全部缺失和保存目录失效。
- 支持文件被外部删除后的重新解析和完整重下。
- 默认下载根目录被删除后，在下一次下载时自动创建。
- 自定义 SAF 目录失效时要求用户重新选择，不静默切换目录。
- 优先使用图文作品的 `download_url_list`，同时保留已有地址作为降级候选。
- 非破坏性升级现有数据库，并为旧任务提供尽力兼容。

## 非目标

- 不持续运行后台文件监控服务。
- 不递归删除任务目录内未经数据库登记的文件。
- 不为图文作品虚构接口没有提供的清晰度档位。
- 不保证恢复已经从抖音源站永久下线的作品。
- 不静默绕过登录、验证码或风控验证。

## 数据模型

### 两套独立状态

任务执行状态与文件可用状态分开保存，避免“下载已完成”等同于“文件仍然存在”。

执行状态包括：

- `QUEUED`
- `PARSING`
- `DOWNLOADING`
- `MERGING`
- `COMPLETED`
- `FAILED`
- `CANCELLED`
- `DELETING`

文件状态包括：

- `UNKNOWN`：旧任务或暂时无法可靠判断。
- `AVAILABLE`：所有预期输出都存在。
- `PARTIAL`：至少一个输出存在，同时至少一个输出缺失。
- `MISSING`：所有预期输出都不存在，或已确认任务目录不存在。
- `STORAGE_UNAVAILABLE`：自定义 SAF 根目录无法访问或持久授权失效。
- `DELETE_FAILED`：同步删除只完成了一部分或发生错误。

### 任务恢复信息

新任务持久化以下信息：

- 抖音作品 ID、作品类型和规范化作品地址。
- 用户原始分享文本或链接，用于诊断和兼容性回退。
- 下载模式：视频、音频、视频与音频、合成。
- 所选视频档位的分辨率、编码、帧率、码率及可用的变体标识。
- 图文作品中每张图片的候选地址列表。

重新下载时不能把旧 CDN URL 当作主要恢复依据。旧地址只保留在诊断数据和最后回退路径中。

### 存储信息

任务记录增加：

- 存储模式：默认公共下载目录或自定义 SAF 目录。
- 默认下载根目录标识，或 SAF Tree URI。
- 任务目录名称及可用的目录 URI/路径信息。
- 预期输出列表；每项包含逻辑类型、显示名称、MIME 类型、URI、相对路径及可用性。

新任务目录使用“时间戳 + 任务短 ID”，保证同一秒创建的任务也不会共用目录。默认根目录为 `Download/DouyinDownloader`。

数据库采用非破坏性版本迁移。旧任务新增字段为可空值或合理默认值，不删除旧记录。

## 组件边界

### TaskStore

负责数据库迁移、任务及输出记录的读写。它不直接访问文件系统，也不负责解析抖音作品。

### StorageInspector

根据任务存储模式检查输出 URI、任务目录和根目录。返回结构化的文件状态及缺失项，不改变文件或数据库。

检查触发点为：应用启动或恢复、进入任务页面、下载/分享/删除完成后、点击异常任务时。任务页周期刷新可以继续更新进度，但存储扫描必须节流，不能每秒遍历全部输出。

### TaskDeletionCoordinator

协调 WorkManager 停止、缓存清理、公共输出删除、空目录删除和数据库记录删除。它执行明确的阶段状态，避免下载线程与删除线程同时写入同一任务目录。

### TaskRedownloadCoordinator

根据持久化作品信息重新解析当前资源，匹配原选择档位，清理任务残留输出并创建新的下载工作。它不盲目复用旧 CDN 地址。

### ImageCandidateResolver

为每张图片生成去重后的候选地址，优先级为：

1. `download_url_list`
2. `origin_url` / `originUrl`
3. `url_list` / `urlList`
4. 解析结果中其他合法的 CDN 备用地址

下载器按顺序尝试候选地址。一个地址失败不能直接使整张图片失败。

## 文件状态判断

对于具有预期输出记录的任务：

- 全部输出可访问时为 `AVAILABLE`。
- 一部分可访问时为 `PARTIAL`。
- 没有输出可访问时为 `MISSING`。
- SAF 根目录或持久授权失效时优先为 `STORAGE_UNAVAILABLE`，不能误判成文件被删除。

旧任务如果没有完整输出清单，先检查已有输出 URI；必要时根据创建时间推测旧默认任务目录。无法可靠判断时保持 `UNKNOWN`，不能直接显示文件已删除。

## 删除流程

任务卡提供删除入口。确认对话框包含“同时删除下载内容”复选框，默认不勾选。

### 仅删除任务记录

取消对应工作后删除数据库记录，不删除公共文件。遗留文件从此不再由应用管理。诊断日志按应用日志保留策略继续保存。

### 同步删除下载内容

1. 将任务标记为 `DELETING`，阻止新下载、重试和分享操作。
2. 取消对应 WorkManager 工作并等待写入停止。
3. 删除该任务的应用私有临时文件和合成缓存。
4. 删除数据库明确登记的公共输出文件。
5. 重新检查任务目录；只有目录确认为空时才删除目录。
6. 全部成功后删除数据库任务记录。

不得通过递归删除清除未知文件。如果用户把其他文件放入任务目录，只删除任务登记的输出，保留未知文件和目录。界面提示任务内容已删除，但目录因包含其他文件而保留。

如果公共内容只删除一部分或删除失败，任务进入 `DELETE_FAILED`，保留任务记录并提供：

- 重试删除。
- 仅删除任务记录。

选择“仅删除任务记录”后，残留文件不再受应用管理。

## 重新下载流程

`PARTIAL`、`MISSING` 和恢复后的 `DELETE_FAILED` 任务允许重新下载。

1. 使用作品 ID、类型和规范化地址重新解析抖音当前页面或接口。
2. 如遇登录、验证码或风控，显示可完整操作的浏览器验证页面；一般解析过程只显示应用内进度。
3. 视频首先匹配原分辨率、编码和帧率；没有完全匹配时选择最接近的档位；仍无法匹配时选择当前可得最高档位并告知用户。
4. 图文作品重新生成每张图片的候选地址列表，优先 `download_url_list`。
5. 保留原下载模式，包括音频下载和可选音视频合成。
6. 停止旧工作并安全清理该任务已登记的残留输出。
7. 在新的唯一任务目录中执行完整重下，并更新任务存储元数据。

重新下载不会保留半套旧输出。音视频合成完成后，原视频和原音频仍然保留，延续现有产品约定。

## 目录与权限行为

### 默认公共目录

默认根目录为 `Download/DouyinDownloader`。下载开始时检查并按需创建根目录和新的任务子目录。根目录被用户删除不构成永久错误。

应用申请“所有文件访问”权限，以便在默认公共目录中进行可靠的目录检查和空目录删除。权限请求只在相关功能首次需要时出现；用户拒绝后，普通下载以及系统仍允许的应用自有 MediaStore 文件操作继续可用。需要该权限但尚未授权时，界面说明原因并打开系统设置，不能报告虚假的删除成功。

### 自定义 SAF 目录

如果保存的 Tree URI 已失效、目录被移动或删除，任务进入 `STORAGE_UNAVAILABLE`。应用提示重新选择保存目录，重新授权后由用户点击重新下载。应用不能静默切换到默认目录，也不能猜测旧自定义目录的父路径。

## 用户界面

- `AVAILABLE`：维持正常任务卡样式和操作。
- `PARTIAL`：橙色，显示“部分文件已删除”；分享时只包含仍存在的文件。点击后提供重新下载和删除任务。
- `MISSING`：灰色，显示“文件已被删除”。点击后提供重新下载和删除任务。
- `STORAGE_UNAVAILABLE`：显示“保存目录已失效”并提供重新选择目录。
- `DELETE_FAILED`：显示“部分内容删除失败”，提供重试删除和仅删除任务记录。

多文件分享继续支持多选。MP4、MP3、JPEG、PNG、WebP 等内容按各自真实 MIME 类型分享；缺失文件从分享列表中排除。如果没有任何可分享文件，则进入恢复提示。

图文作品默认选择每张图片当前可获得的最高质量地址。除非接口真实提供不同尺寸的资源，否则不显示人为构造的图片清晰度档位。

## 旧任务兼容

- 旧默认目录任务根据已有 URI和创建时间尽力重建关联。
- 旧自定义 SAF 任务只删除已知文件；仅在父目录可可靠解析且为空时删除目录。
- 旧任务缺少文件元数据时可以保持 `UNKNOWN`，不进行危险猜测。
- 旧任务重新下载后迁移到新的唯一任务目录，并写入完整的新元数据。

## 错误处理与日志

关键阶段写入本地诊断日志：状态扫描、授权检查、重新解析、档位匹配、候选地址切换、工作取消、逐文件删除和目录删除。日志不得记录 Cookie、授权令牌或完整敏感请求头。

用户可见错误使用可执行的下一步提示，例如重新授权、重新选择目录、重试解析、重试删除或仅删除记录。内部异常不能直接以堆栈信息展示给用户。

## 测试策略

### 单元测试

- 数据库从旧版本迁移且任务不丢失。
- 文件状态的完整、部分缺失、全部缺失、未知和 SAF 失效判断。
- 文件夹含未知文件时不会被删除。
- 图片候选地址排序、去重与失败切换。
- 视频原档位精确匹配、最接近匹配和最高档位回退。
- 删除中状态阻止下载、分享和重试。

### 集成测试

- 运行中的下载或合成被删除时，写入先停止再清理。
- 默认下载根目录被外部删除后，下次下载自动重建。
- SAF 授权失效后暂停并重新选择目录。
- 部分公共文件删除失败时保留任务记录，并可重试或仅删除记录。
- 重新下载重新解析资源，而不是直接复用旧 CDN URL。
- 多图片、多 MIME 类型分享保持可用。

### 设备验收

在一加 13T 上验证：所有文件访问授权及撤销、文件管理器外部删除单个文件和整个目录、部分图片缺失、默认根目录重建、自定义目录失效、重新下载、音频下载、音视频合成、原始音视频保留、任务删除和多格式分享。

## 完成标准

- 用户可以安全选择“仅删任务”或“任务与下载内容一起删除”。
- 外部删除后，任务卡在下一次受控检查中显示正确状态。
- 任何删除路径都不会递归清除未知文件。
- 缺失任务能够重新解析并恢复到当前可获得的最合适质量。
- 图片下载优先使用 `download_url_list`，并能自动切换备用地址。
- 旧任务和已有下载不因数据库升级而丢失。
- 新 APK 输出到 `/mnt/Android/douyinDownload`，并通过上述设备验收流程。
