# 平台解析增强、实况照片与应用更新设计

日期：2026-09-05

## 目标

在不改变现有抖音、小红书、知乎下载行为和任务数据的前提下，完成三项增强：

1. 为抖音和小红书增加有顺序、可诊断的解析回退策略，提高旧作品、受风控页面和页面结构变化时的成功率。
2. 识别抖音和小红书的实况照片，保留原始静态图片与动态视频，并额外生成兼容 Android 相册的 Motion Photo。
3. 在设置页增加安全的更新检查和手动更新能力，支持镜像加速与 GitHub 原始源。

项目继续保持纯 Kotlin、本地解析、不依赖远程解析服务器。实现只研究其他项目公开展示的接口行为和处理思路，不复制或翻译 AGPL 源码。

## 非目标

- 不增加远程解析服务。
- 不自动下载或静默安装更新。
- 不承诺绕过平台登录、验证码、付费、私密内容或访问控制。
- 不把“当前最高候选”描述为作者上传前母版。
- 不在本次开发中增加作者主页批量下载。
- 不引入 ffmpeg、Python 或新的原生二进制库。

## 解析策略架构

保留现有 `PlatformParser` 对外接口。平台解析器内部改为顺序策略链，每个策略只负责请求、验证并返回平台详情对象；现有标准化器继续把详情对象转换为 `ParseResult`。

策略执行遵循以下规则：

- 前一策略成功且返回的内容 ID 与目标 ID 一致时立即停止，不发起多余请求。
- 空响应、已知结构缺失和可恢复的 HTTP 错误进入下一策略。
- 登录或风控错误保留明确错误类别，供 `ParserGateway` 决定是否进行一次 WebView 预热重试。
- 任何可能返回推荐流或页面中其他作品的入口必须严格核对内容 ID，避免下载错误作品。
- 每次尝试记录策略名、HTTP 状态、响应形状和失败类别；日志不记录 Cookie、签名值或完整带查询参数 URL。
- 所有扫描都有深度、节点数和响应体大小上限，避免异常页面造成长时间阻塞或内存膨胀。

### 抖音

抖音按以下顺序解析：

1. 当前带 `a_bogus` 的 Web Detail 接口。
2. `iteminfo` 结构化详情接口。
3. 移动端 Feed 接口；只接受列表中 `aweme_id` 与目标完全一致的对象。
4. `share/video` 页面中的路由初始状态。
5. `share/note` 页面中的路由初始状态。
6. 桌面 Note 页面初始状态中的目标作品数据。

标准化阶段继续遵守已有媒体优先级：图文作品优先识别图片，图片候选中优先 `download_url_list`，随后才是原图字段和普通 `url_list`。视频保留 `bit_rate` 中全部可用档位和最高音频轨，不退化成只选择一个 URL。

若所有最新解析入口均失败，重新下载仍可使用任务中保存且预检有效的旧 CDN 地址；新任务不存在旧地址时返回包含最终失败原因的错误。

### 小红书

小红书解析顺序为：

1. 从已知的 `noteDetailMap`、`note`、`feed` 等路径查找目标 Note。
2. 在页面初始状态中执行有界深层扫描，最多访问 50,000 个节点、最大深度 12，只接受包含目标 Note ID 的候选。
3. 常规 HTTP 页面缺少状态时，使用当前 WebView 页面快照重新执行前两步。

图片候选兼容显式原图字段、`urlDefault`、`traceId`、`infoList` 和可恢复的 CDN 对象路径。视频兼容 `originVideoKey` 以及不同编码下的 Stream 数组，并继续保留所有可用清晰度，而不是强制只取一个地址。

## 实况照片模型与下载

在统一媒体模型中增加可选的 `LivePhotoPair`：

- 静态图片候选列表。
- 动态视频候选列表或档位。
- 与作品中图片位置对应的稳定索引。
- 可选的平台元数据。

`ParseResult.livePhotos` 默认是空列表。JSON 反序列化缺少该字段时按空列表处理，因此已有任务和数据库记录不需要迁移或清空。

下载规则：

1. 先分别下载原始静态图片和动态视频到任务暂存目录。
2. 两个源文件都完整且格式有效时，生成一个新的 Motion Photo 文件。
3. 发布原图片、原视频和合成文件，三者都进入任务输出列表。
4. 合成失败时仍发布原图片和原视频，并将失败记录为非致命警告。
5. 取消或失败时遵循现有事务式下载语义，不删除旧任务内容。

Motion Photo 使用 Android 公布的 XMP 元数据和 JPEG/MP4 拼接结构实现，不重新编码视频。对于相册厂商不识别的设备，文件仍可作为普通 JPEG 查看，原视频也始终保留。

预览继续使用现有图片和视频播放器。合成文件作为图片预览，原动态视频可以独立播放。分享和应用内文件管理无需特殊协议，只按实际 MIME 类型处理。

## 更新检查与手动更新

### 检查行为

- 设置页增加“更新”分区，显示当前版本和最近一次检查结果。
- 用户可以随时点击“检查更新”。
- 应用启动后可以自动检查发布元数据，但同一自然日最多一次。
- 自动检查只更新设置页中的“发现新版本”提示，不弹窗、不下载 APK。
- 检查失败不影响应用启动、解析或下载，也不循环重试。

最新版本来自 `Lyx10000/media-downloader-android` 的 GitHub Releases latest API。下载前使用规范化后的版本号判断是否有新版；APK 下载完成后再读取并校验其中的 `versionCode`。预发布版本不作为稳定更新推送。Release 中优先选择名称包含 `arm64` 的 APK，否则选择唯一 APK；存在多个无法判定的 APK 时只打开 Release 页面，不自动选择。

### 下载源

用户点击“立即更新”后选择：

- 镜像加速：默认推荐，首个版本使用 `https://gh-proxy.org/` 转发 GitHub Release 资产 URL。镜像失败后提示用户，只有用户确认才切换 GitHub 原始源。
- GitHub 原始源：开始前提示“部分网络环境未开启代理时可能速度很慢或下载失败”，用户确认后才继续。

镜像地址集中定义，后续增加或替换镜像时不改动更新业务逻辑。下载请求限制重定向次数，并只允许 HTTPS。Release 元数据仍以 GitHub API 的结果为准，镜像不能改变目标版本、文件名或预期包信息。

### 下载、校验与安装

- APK 下载到应用私有缓存目录，显示真实字节进度、速度和总大小。
- 使用临时文件下载，完整结束后再原子重命名为 `.apk`。
- 安装前通过 `PackageManager` 读取归档信息并验证：包名等于当前应用、`versionCode` 高于当前版本、签名证书 SHA-256 与当前已安装应用一致。
- 如果 Release 同时提供匹配文件名的 SHA-256 清单，再额外校验文件摘要；没有清单时签名证书校验仍为强制条件。
- 任一校验失败立即删除缓存文件，不调起系统安装器，并写入脱敏诊断日志。
- 使用 `FileProvider` 和系统 Package Installer 安装。缺少“安装未知应用”权限时，引导用户进入当前应用的系统授权页，返回后由用户再次点击安装。
- 安装完成后的遗留 APK 在下次启动时清理；下载失败的临时文件立即清理。

## 状态与界面

更新状态由独立 `UpdateRepository` 管理，包含空闲、检查中、已是最新、发现新版、检查失败、下载中、校验中和等待安装。状态通过 `MainViewModel` 暴露给设置页，但不混入下载任务数据库。

更新日志在对话框中以受限的纯文本/基础 Markdown 展示，不加载远程图片或脚本。下载对话框可取消；取消会关闭网络流并删除临时文件。

## 诊断日志

新增以下事件：

- `PARSE_STRATEGY_STARTED`、`PARSE_STRATEGY_FAILED`、`PARSE_STRATEGY_SELECTED`
- `LIVE_PHOTO_DETECTED`、`LIVE_PHOTO_COMPOSED`、`LIVE_PHOTO_COMPOSE_FAILED`
- `UPDATE_CHECK_STARTED`、`UPDATE_AVAILABLE`、`UPDATE_CHECK_FAILED`
- `UPDATE_DOWNLOAD_STARTED`、`UPDATE_SOURCE_FAILED`、`UPDATE_VALIDATION_FAILED`、`UPDATE_INSTALL_REQUESTED`

日志只保存策略名、状态码、版本、字节数、镜像序号和错误类型。下载 URL 查询参数、Cookie、签名、证书原文和设备账号信息必须脱敏或省略。

## 兼容性和失败处理

- 应用 ID、签名证书、最低 Android 版本和现有 Room 数据库保持不变，可覆盖安装。
- 新模型字段全部提供默认值，旧任务仍可预览、分享、删除和重新下载。
- 平台解析的新增回退只在前序入口失败时执行，避免正常解析变慢。
- 更新服务不可用时，设置页显示可重试错误，不影响其他页面。
- 第三方镜像仅作为传输通道，未经签名一致性校验的 APK 永远不会进入安装流程。

## 测试与验收

单元测试覆盖：

- 每个解析策略的成功、空响应、错误状态和严格内容 ID 校验。
- 抖音图文不会把 BGM 当视频；`download_url_list` 仍优先。
- 小红书已知路径、深层扫描、扫描上限、`traceId`、`infoList`、原图路径和 Live Photo 配对。
- 新旧 `ParseResult` JSON 的双向兼容。
- Motion Photo 元数据、文件偏移、源文件保留和合成失败降级。
- 版本比较、Release 资产选择、每日检查节流和预发布过滤。
- 镜像失败不静默切换、GitHub 源警告、取消下载和临时文件清理。
- 包名、版本号、签名与可选 SHA-256 校验。

使用 MockWebServer 验证重定向、超时、分段响应和下载进度。完成后运行全部 JVM 测试、Android lint、release 编译和 R8；签名 APK 后验证证书、包名和可覆盖安装条件，再复制到共享目录。真实平台链接只作为人工冒烟测试，不把短期 CDN URL 提交到测试资源中。

## 提交边界

实现拆分为三个可独立审查和回退的提交：

1. 抖音与小红书解析策略链及诊断。
2. 实况照片统一模型、下载与预览。
3. 更新检查、镜像下载、安全校验与安装界面。

不修改工作区中与本设计无关的历史删除项和临时文件。
