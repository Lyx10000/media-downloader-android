# X 单帖子媒体下载支持设计

日期：2026-09-06

## 背景与目标

聚合下载器当前支持抖音、小红书和知乎。本次为 Android 端新增 X 单帖子媒体下载，保持纯 Kotlin、本机运行，不集成 Python、yt-dlp 或远程解析服务器。yt-dlp 仅用于研究公开接口行为和回退思路，不复制其源码。

首版目标是可靠下载 X 原生托管的图片、视频和 GIF，并复用现有任务、日志、预览、分享、删除和事务式重新下载能力。

## 范围

首版支持：

- `x.com/{user}/status/{id}`、`twitter.com/{user}/status/{id}` 及对应移动端、查询参数链接。
- 单帖子内最多四个、可混合排列的图片、视频和 GIF 附件。
- 图片最高可用候选；视频全部直连 MP4 档位及逐视频清晰度选择。
- 匿名优先解析；需要登录、年龄验证或访问授权时使用 X 登录环境和 Cookie 重试。
- 普通转帖解析原帖媒体；引用帖只下载当前帖子直接上传的媒体。
- X 平台标签、作者昵称、可复制的 `@用户名`、帖子文案任务标题。

首版不支持：

- 纯文本帖子的 Markdown 或文本归档。
- 帖子内 YouTube、TikTok 等外部媒体链接的递归解析。
- X Spaces、直播、广播和作者主页批量下载。
- 被引用帖媒体的自动下载。
- HLS 分片下载。只有 HLS、没有直连 MP4 时给出明确提示。
- 私密账号中当前登录用户无权访问的内容。

## 架构

### 平台接入

在 `SourcePlatform` 中新增 `X`，识别 `x.com`、`twitter.com` 及其常用子域名。平台展示采用黑色背景和白色文字，显示名为 `X`。

新增三个职责独立的组件：

- `XSourceResolver`：提取状态链接和帖子 ID，移除无关查询参数，生成规范化 `x.com` 链接。
- `XPlatformParser`：执行解析路线、状态分类和有限回退。
- `XMediaNormalizer`：把不同响应结构转换成统一作者、文案和附件模型。

`KotlinParserRouter` 注册 X 解析器。抖音、小红书和知乎解析器不改行为。

### 附件模型

新增可序列化的 `MediaAttachment`，字段至少包括稳定附件 ID、原始顺序、附件类型、封面、图片候选和视频档位。附件类型区分图片、视频和 GIF。

`ParseResult` 新增默认为空的附件列表；现有平台继续使用原字段。`TaskSpec` 新增逐附件清晰度选择列表，以附件 ID 关联所选档位。旧 JSON 缺少新字段时按空列表读取，因此不需要 Room 数据库迁移。

下载执行器先判断附件列表：为空时走原有单媒体逻辑，非空时走多附件逻辑。这样不会改变三个现有平台的下载行为。

## 解析流程

1. 从分享文本提取第一个受支持的 X 状态链接，并严格校验数字帖子 ID。
2. 匿名尝试公开帖子元数据入口。
3. 必要时激活访客会话并请求访客 GraphQL 帖子详情。
4. 如果服务端明确要求认证，提示用户进入 X 登录环境；登录后使用 `auth_token` 与 `ct0` 对应的会话和 CSRF 信息重试。
5. 常规 HTTP 路线无结果但目标页面可访问时，使用隐藏 WebView 页面快照作最后回退。
6. 每条路线最多执行一次。`429`、明确风控或挑战页立即停止，不进行循环刷新。
7. 所有结果必须与目标帖子 ID 对应。普通转帖允许解析为其明确指向的原帖；引用帖不把被引用内容并入附件。
8. 归一化帖子文案、作者昵称、`@用户名`、头像、附件顺序、图片候选及直连 MP4 档位。

官方开发者 API 不作为默认路线，因为它要求应用级凭据；APK 中不内置开发者密钥，也不要求普通用户配置 Bearer Token。

## 媒体与下载行为

### 图片

图片候选优先请求最高可用版本，并保留 CDN 返回的真实 MIME 类型和扩展名。如果最高候选失效，按候选顺序回退。文件按附件原始顺序命名为 `image_001.*` 等。

### 视频与 GIF

每个视频附件独立保存全部直连 MP4 档位，按分辨率、码率和大小排序，默认选择最高档。解析阶段并发探测大小但限制并发数，探测失败只显示“大小未知”，不阻止下载。

普通视频复用现有四种处理模式。X 的视频通常是内嵌音频 MP4，现有媒体轨道处理器负责保留完整文件或无损拆分音视频轨。多视频任务对每个普通视频应用同一个处理模式，但清晰度逐视频选择。

GIF 作为无声 MP4 保存，不显示仅音频或音视频分轨选项。混合媒体任务中的图片和 GIF 始终保存；视频处理模式只作用于普通视频附件。

首版忽略 HLS 候选。不存在直连 MP4 时返回 `HLS_ONLY`，不把播放列表误当作 MP4 下载。

### 文件、进度和恢复

一个帖子对应一个任务目录，附件按原始顺序命名，例如 `image_001.jpg`、`video_002.mp4`、`gif_003.mp4`。存在拆分轨道时在对应序号后增加 `_video`、`_audio` 或 `_source`。

任务进度以实际媒体下载字节为主，并显示当前附件序号、下载速度和总体百分比。完成后以实际输出文件重新统计任务大小。

任务保存规范化帖子链接、附件元数据和逐附件选择。重新下载时先重新解析并验证远端资源，新内容完整落盘后才替换旧输出；失败或取消保留旧文件。

## 界面与预览

解析结果页显示 X 标签、作者昵称、`@用户名`、帖子文案和附件总数。图片显示“最高可用图片”；视频/GIF 以附件卡片按原顺序展示。单视频沿用现有清晰度交互，多视频允许展开后逐个选择，默认全部最高。

任务标题使用帖子文案；文案为空但存在媒体时使用“X 媒体帖子 + 帖子 ID”兜底。任务卡片显示作者昵称，并在下一行显示可复制的 `@用户名`。

预览器按输出顺序浏览全部图片、视频和 GIF；同一时间只播放一个视频。分享、文件夹操作、删除、批量操作和平台筛选沿用现有任务能力。

纯文本、只有外部链接或没有可下载附件的帖子显示说明，不创建任务。

## X 登录环境

未检测到 X 登录凭据时直接进入 X 登录流程，不停留在仅引导打开官方 App 的落地页。已登录时显示明确状态，但仍允许进入账户页面退出登录。

WebView 不注入固定缩放、横向位移或锁定视口脚本。网页支持上下左右滑动和双指缩放；系统返回键优先返回 WebView 历史。键盘弹出后当前输入框必须保持可见，输入顺序不得被 JavaScript 或布局变换影响。

顶部应用工具栏提供关闭、刷新和转到登录页，且不遮挡网页。页面错误、验证码、频率限制和登录状态说明放在可滚动区域。登录完成后刷新 Cookie 并检测 `auth_token`、`ct0` 的存在，再允许重试解析。Cookie 值不写入日志。

## 错误与日志

对用户区分以下错误：

- `UNSUPPORTED_URL`：不是受支持的 X 状态链接。
- `POST_UNAVAILABLE`：帖子不存在、已删除或不可见。
- `PROTECTED_POST`：受保护账号且当前会话无权访问。
- `LOGIN_REQUIRED`：需要登录或年龄确认。
- `RATE_LIMITED`：请求频繁，需要稍后重试。
- `MEDIA_EMPTY`：帖子没有直接附加的可下载媒体。
- `HLS_ONLY`：只有首版暂不支持的 HLS。
- `RESPONSE_CHANGED`：接口成功但响应结构无法识别。
- `NETWORK`：网络或 CDN 请求失败。

诊断日志记录解析策略、目标帖子 ID、HTTP 状态、最终主机、附件数量、附件类型、视频档位数量、大小来源和失败阶段。Cookie、Bearer Token、访客令牌、CSRF Token、GraphQL 变量中的敏感值和媒体 URL 签名参数必须脱敏。

## 验证与验收

自动测试覆盖：

- X 与 Twitter 各类状态链接、查询参数和不支持路径。
- 图片、视频、GIF、混合媒体、多个视频、转帖和引用帖固定响应样本。
- GraphQL 包装结构、登录要求、删除、保护、限流、空媒体及 HLS-only 分类。
- 附件序列化、逐附件档位选择和旧 `TaskSpec` 兼容。
- 多附件下载命名、进度聚合、取消和事务式重新下载。
- X Cookie 名检测、登录页导航、网页滚动、缩放、键盘输入及返回行为。
- 任务平台筛选、标题、作者信息、预览和分享。

首轮交付为不启用 R8 的可覆盖安装测试包，不创建 GitHub Release。测试包通过真机 X 图片、单视频、GIF、混合媒体、多个视频、转帖、引用帖和登录受限样本后，再以 R8 构建正式 `1.7.0`。
