# 作者库与批量下载设计

## 目标

在不改写现有单作品解析、后台下载、日志、重试、预览和文件管理链路的前提下，增加作者资料、公开作品浏览、跨页选择、批量下载和作者目录。首期覆盖抖音、小红书和知乎，并为后续平台保留适配接口。

## 产品结构

任务页内部增加“任务 / 作者”两个页签，不新增底部导航。

- “任务”保留现有单作品任务列表。作者批量下载生成的子任务不在这里逐条堆叠。
- “作者”展示每个平台的作者入口，支持“全部 / 抖音 / 小红书 / 知乎”筛选。平台筛选作为独立提交交付。
- 作者详情采用统一骨架：资料头部、动态统计字段、“公开作品 / 下载记录”页签。
- 作者卡片显示批次聚合进度；作者详情仍可查看每个作品的独立状态。

首页增加“作品解析 / 查找作者”模式：

- 完整主页链接自动识别平台。
- 纯账号需要先选择抖音或小红书；知乎只接受主页链接，不按可重复的昵称查找。
- 抖音接受抖音号或主页链接，小红书接受小红书号或主页链接。
- 查找成功后先展示匹配资料，由用户确认加入作者库，不静默采用第一个模糊结果。

## 统一数据模型

### 作者

作者唯一键为 `平台 + 平台稳定内部用户 ID`，不按昵称或公开账号合并，也不跨平台合并。

公共字段包括：平台、稳定 ID、公开账号、主页 URL、头像、昵称、简介、公开位置、动态统计项、账号状态、是否关注、首次加入时间、最后刷新时间和刷新错误。平台不存在的字段不显示。

账号状态包括：公开、私密或受限、明确注销、暂不可访问、未知、刷新失败。只有平台明确返回注销信息时才标为注销；网络错误、风控、未登录、404 或本页未出现均不能推断注销。

停止关注没有下载记录的作者时可直接移除；有下载历史的作者转入本地归档并停止自动刷新。归档作者可重新关注并复用原记录。彻底删除时允许只删记录保留文件，或连作者目录一起删除。

### 作品索引

作品唯一键为 `平台 + 作品 ID`，关联作者稳定键。保存作品类型、标题、封面、发布时间、详情链接、粗略时长和尺寸信息、分页来源、最后发现时间以及远端状态。

远端状态与本地文件状态分离：

- 远端：公开、本次未探测到、明确不可用、检查失败、未知。
- 本地：未下载、等待、下载中、可用、部分缺失、已删除、失败。

“本次未探测到”只说明当前已加载公开页没有发现，不能显示为已删除。只有直接详情请求明确返回不可用时才升级为“明确不可用”。本地文件永不因远端状态变化自动删除。

### 任务关联

现有任务增加可选作者稳定键、批次 ID 和“作者子任务”标志。直接下载的作品仍出现在普通任务页；能确定作者稳定 ID 时，同时出现在该作者的下载记录中，但只保留一条任务和一份文件。

旧任务不按昵称强行归属。后续重新解析作品或刷新作者时，如果拿到稳定 ID，再进行惰性关联。

## 平台适配层

新增统一作者数据源接口，职责只有三项：

1. 按主页链接或公开账号解析作者；
2. 获取并归一化作者资料；
3. 使用平台游标获取一页公开作品。

抖音适配器使用稳定 `sec_uid`；小红书使用内部 `user_id` 并保留页面提供的安全上下文；知乎使用主页 `url_token`。平台接口、签名、Cookie 和页面状态解析留在各自适配器内，通用作者层不认识平台 JSON 字段。

所有平台错误归一为：需要登录、风控限制、网络失败、作者不存在、作者受限、游标失效和页面结构变化。错误必须保留平台、阶段和安全脱敏后的原因到诊断日志。

## 分页、选择与刷新

平台接口使用游标，但界面呈现明确的“上一页 / 第 N 页 / 下一页”。已加载页面在本地缓存，返回上一页不立即重复请求。

- “全选当前页”只选择当前页尚未完整下载的作品。
- 已下载作品显示“已下载”标签并默认跳过；汇总显示本页数量、选中数量和跳过数量。
- 用户仍可单独选择已下载作品，选择时明确提示将重新下载并替换登记文件。
- 任务记录存在但文件缺失的作品显示“本地已删除”，可直接选择重新下载。
- 跨页选择持续保留。第二页及以后继续全选或累计数量达到风险阈值时，每个作者浏览会话提醒一次大量请求可能触发风控。
- 不提供“一次选择作者全部作品”，避免不可控抓取。

进入作者详情先显示缓存。缓存超过六小时才自动刷新，否则仅在用户主动刷新时请求平台。界面始终显示最后成功更新时间；刷新失败保留旧缓存。

## 下载前统一设置

开始批量下载前展示统一设置界面，设置只作用于当前批次，并记住上一次选择作为下次默认值：

- 视频质量：最高、最高不超过 1080p、最高不超过 720p。
- 音视频处理：合成并保留原轨、分别下载、仅视频、仅音频。合成后不删除原视频和音频。
- 图片：获取平台当前可提供的最高质量。
- 实况：保留图片与动态片段，并在支持时生成动态照片。
- 知乎图文：保存 Markdown 和全部可下载媒体。

作品没有目标档位时，选择不高于目标的最高档位；若全部高于目标或元数据不足，则使用平台可提供的最高档位并在批次摘要中提示。

## 大小与空间估算

估算不额外探测每个 CDN。按作品类型、时长、目标质量和本机历史下载均值计算区间，并明确显示“约”。同时显示当前保存位置的可用空间和总空间；SAF 提供方无法报告容量时显示“存储提供方未提供容量”。估算接近或超过可用空间时警告，但不硬性阻止下载。

## 下载执行与失败隔离

批次记录保存统一策略和选中作品。批次调度器按受控并发逐个解析作品详情，再创建现有 `TaskSpec` 和 WorkManager 工作；每个作品拥有独立任务、日志、重试和文件事务。

批次不是全有或全无：单个作品失败不终止其他作品。遇到明确风控时暂停继续提交，展示已完成、失败、跳过和待继续数量，允许用户稍后继续。

## 文件布局

作者下载使用稳定目录：

```text
聚合下载器/
  平台/
    作者名_公开账号_稳定ID后8位/
      作品日期_作品ID/
        媒体文件
```

目录首次建立后不因改名、改号或注销自动重命名。单作品原有任务仍兼容旧目录；新关联作者的下载使用作者目录。任务记录保存相对目录，SAF 和默认公共目录走同一逻辑。

## 页面状态与可访问性

作者列表和公开作品列表必须有独立的加载、空数据、缓存、失败和归档状态。刷新期间继续显示缓存，不用整页进度圈覆盖内容。状态标签不能只靠颜色表达，批量设置和破坏性操作均提供明确文本。

## 数据库迁移

Room 增加作者、作者作品、批次和批次作品表；任务表增加可空作者键、批次 ID 与作者子任务标记。迁移只添加数据，不重写现有任务 JSON，不破坏 1.6.x 数据。

## 测试与提交边界

测试覆盖：稳定键、平台归一化、分页缓存、跨页选择、已下载跳过、状态合并、粗略估算、统一质量选择、作者目录净化、数据库迁移、批次失败隔离和任务可见性。

提交分组：

1. 设计文档；
2. 作者库、主页查找、批量下载和作者目录主体（含测试）；
3. 作者页平台筛选（含测试）。

不会纳入工作区中既有的无关删除和临时文件。
