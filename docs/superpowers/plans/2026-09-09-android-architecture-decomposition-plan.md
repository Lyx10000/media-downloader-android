# Android 架构渐进式拆分实施计划

依据：`docs/superpowers/specs/2026-09-09-android-architecture-decomposition-design.md`

## 执行规则

- 保持单一 `app` Gradle 模块。
- 不改变应用 ID、数据库、任务标识、WorkManager 名称、目录和用户行为。
- 每个步骤先运行定向测试，再运行完整单元测试和 Debug 构建。
- 每个阶段独立提交；测试包使用正式证书签名但关闭 R8。
- 不纳入工作区已有的无关删除和未跟踪文件。

## 阶段一：Compose 页面拆分

1. 将首页登录 WebView、登录辅助策略和页面快照桥接 UI 移入独立文件。
2. 将首页解析结果、质量选择和错误/加载状态移入独立文件。
3. 将任务页作者批次卡片、子任务明细和批量对话框移入独立文件。
4. 将任务预览、分享和文件管理入口按职责拆分。
5. 将作者列表、资料头部、公开作品和本地作品区域拆分。
6. 保持原页面入口函数及导航调用兼容，运行 Compose 编译和现有 UI 逻辑测试。

## 阶段二：MainViewModel 拆分

1. 为解析会话补充输入、重试和状态转换表征测试。
2. 提取 `ParseSessionController`，由 `MainViewModel` 薄委托。
3. 为登录状态检测补充生命周期和凭据状态测试。
4. 提取 `PlatformCredentialCoordinator`。
5. 提取 `TaskCommandCoordinator`，集中暂停、继续、取消、重试和批量操作。
6. 提取 `TaskContentCoordinator`，集中预览、分享、文档和文件操作。
7. 提取设置、日志和更新操作协调器。
8. 删除迁移完成后的重复字段和私有实现，保持 `MainUiState` 兼容至页面迁移完成。

## 阶段三：DownloadExecutor 拆分

1. 为候选 CDN、单流下载、重试、进度和短文件速度建立表征测试。
2. 提取 `MediaTransferClient`，原执行器通过委托调用。
3. 提取 `OutputPublisher`，保持事务式重新下载顺序。
4. 依次提取图片、附件、文档和视频执行器。
5. 保持 B站音视频并行、MP4-only、原轨保留和合成语义。
6. 验证取消传播、临时文件清理、输出登记和错误日志不变。

## 阶段四：平台适配层整理

1. 将 `PlatformParsers.kt` 中具体平台入口逐个平台移回对应平台包。
2. 公共包保留 `PlatformParser`、路由和通用错误模型。
3. 检查每个平台作者数据源、登录检测和解析器的依赖方向。
4. 通过六个平台现有解析测试验证行为等价。

## 阶段五：状态边界与清理

1. 统一任务活动投影、本地内容投影和运行时采样的映射函数。
2. 删除无调用者兼容方法和重复状态判断。
3. 检查 `core` 对 `feature`、公共平台层对具体平台实现的反向依赖。
4. 更新架构说明、源码目录说明和必要注释。
5. 运行完整测试、非 R8 测试包验证；正式发布时再执行 R8。
